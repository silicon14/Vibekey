# Windows 手工测试清单

Vibekey 的 Windows 前端无法在 Linux 上运行，合并前请在真实的 Windows 7 SP1 / Windows 10/11 上按本清单验证。
每次发布建议至少跑 P0。

## 准备

1. 下载 dist/vibekey-<version>-win7-x64/vibekey.exe（32 位系统用 win32 目录）。
2. 放到不含空格和中文的目录，例如 C:\Tools\vibekey\vibekey.exe，双击运行。
3. 确认 %APPDATA%\Vibekey\ 下生成 config.toml、vibekey.log；托盘出现图标。

## P0 核心功能

- [ ] 首次启动：托盘图标存在，config.toml 含示例片段，日志无 ERROR。
- [ ] 资源管理器与任务栏显示内嵌蓝色 V 图标（不是通用空白程序图标）；exe 属性的 FileDescription 为“Vibekey 文本片段输入工具”，版本与 Cargo.toml 一致。
- [ ] 记事本中按 Alt+1：插入示例片段文字，剪贴板内容在约 0.3 秒后恢复原状。
- [ ] 先把纯文本 A 复制到剪贴板，触发片段后剪贴板应恢复为 A；连续快速触发两次不同片段，插入的文字正确且剪贴板仍是 A。
- [ ] 复制一个文件或图片到剪贴板，再触发片段：片段应以“逐字符输入”方式插入，剪贴板里的文件/图片仍在（不被覆盖）。
- [ ] 带菜单栏的程序（记事本/资源管理器/Office）中按 Alt+1：不弹出/激活目标程序菜单，文字插入到文档/输入框。
- [ ] 按住 Alt+1 不放：只插入一次，不会向目标程序重复发送 Alt+1（无 beep、无重复文本）。
- [ ] 设置 hold 模式后：快速点按 Alt+1 不触发；按住 Alt 约 1 秒再按 1 触发。
- [ ] 浏览器输入框 / 微信 / Word 中按 Alt+1：中文正常插入，无乱码、无丢字。
- [ ] Alt+反引号（键盘左上角 · 键）：光标附近弹出片段列表；↑↓ 移动；Enter 插入；Esc 关闭；点击其它窗口自动关闭。
- [ ] Alt+Backspace：配置菜单弹出，各菜单项可点击；菜单不会因失焦立刻消失。
- [ ] 编辑 config.toml 增加 1 个片段，保存后 2 秒内自动生效（无需重启）。
- [ ] 把 config.toml 改坏（例如少一个引号）：程序不崩溃，托盘气泡提示，旧配置继续可用；修复后自动恢复。
- [ ] 退出菜单：进程结束、托盘图标消失、日志有退出记录。
- [ ] 再次启动：单实例生效（第二个实例立即退出，不出现第二个托盘图标）。

## P0 图形界面与快速编辑

- [ ] Alt+反引号打开单行片段选择器：无标题、结果数或底栏；搜索框与 ☰ 菜单同行；每项以 Alt 槽位徽标 + 名称 + 内容单行显示。默认最大约 460×270 逻辑像素、34 行高、最多 6 行，第一项不得被滚动裁掉。
- [ ] 弹窗为约 95% 不透明度，背景轻微透出但中文/预览/快捷键清晰；GetLayeredWindowAttributes 可读到 242，禁用或模拟不支持时能回退不透明且功能正常。
- [ ] 搜索名称、完整片段内容和 `Alt+1` 均能过滤；多个空格分隔的关键词按 AND 匹配；无结果时显示中文空状态，Esc 可关闭。
- [ ] 搜索框按 ↓/↑ 聚焦列表；Enter 插入当前项；单击、双击、键盘选择和失焦关闭保持原有行为。
- [ ] 列表选中项按 F2 或右键条目进入同一片段的快速编辑；☰ 能打开完整菜单，新建片段、设置等命令可用，Esc 可关闭菜单。
- [ ] 设置中心三个页面可切换、窗口可缩放；片段库的搜索、新建、复制、删除均可用，删除有确认且默认选择“否”。
- [ ] 选中片段后直接修改名称、Alt 槽位、多行正文、插入后 Enter、启用状态；切换条目后内容不丢；模板变量插入到正文当前光标。
- [ ] “应用”后 config.toml 原子更新、窗口保持打开，新片段立即可用；“保存并关闭”同样生效；未应用更改取消时有确认且不写文件。
- [ ] 两个片段选择同一 Alt 槽位、槽位与列表/菜单热键冲突、hold_ms 非数字、timeout_secs 非数字或为 0 时保存被阻止并显示中文错误，旧配置仍可用。
- [ ] 设置窗口打开期间用记事本外部修改 config.toml，再点“应用”：出现外部修改确认，不会静默覆盖。
- [ ] “输入与快捷键”页修改 paste/type、剪贴板恢复、hold、全局热键、ignore_apps、开机启动后，各字段与运行时行为均生效。
- [ ] “同步与备份”页分别清除登录/加密密码：点击按钮但未应用时保留原密码；应用后对应 secret.bin 或 sync-encryption.bin 被清除，密码不会写入 TOML 或日志。加密页在默认和最小窗口下所有新增控件均可见、不重叠。
- [ ] 在 125%/150%/200% DPI 与多显示器下验证弹窗、三页设置窗口和缩小后的最小尺寸；所有输入项仍可到达，列表与按钮不重叠。

## P0 文本剪贴板历史

- [ ] 在正常交互桌面中复制两段不同 Unicode 文本（其中一段包含多行和字面量 `{date}`），Alt+V 能按最新在前显示两项；再次复制旧内容会去重置顶，最多保留 50 项。
- [ ] 历史支持全文搜索、↑↓、Enter、单击、Esc；多行只折叠显示，粘贴保留完整原文，`{date}` 不被展开为日期。
- [ ] 在列表中按 Delete 只删除选中项；搜索栏“清空”和配置菜单“清空剪贴板历史”均有效，空状态正常。
- [ ] 复制图片或文件不会生成历史项；复制浏览器/Office 富文本时只记录其 Unicode 纯文本表示，不声称保留图片或格式。
- [ ] 触发片段或粘贴历史后，内部写入和 250ms 后的剪贴板恢复不会新增/重排历史；连续快速复制 + 注入也不会自采集。
- [ ] 设置窗口保持打开时再复制文本，历史仍能收到通知；设置里的 history 热键可修改，冲突/空值会阻止保存。
- [ ] `%APPDATA%\Vibekey` 不出现历史明文文件，日志不含复制内容；退出并重启后历史为空，WebDAV 不同步历史。
- [ ] Win10/11 的系统 Win+V 默认不被占用；若用户手动配置 `hotkeys.history = "win+v"`，应明确其会替换系统面板。

### 本机自动化冒烟（2026-11-10）

已在 Windows 11 x64、200% DPI 的隔离调试实例中通过：新建/编辑/应用片段、单行搜索、空白点击保护、F2 内容身份匹配、
未保存插入后的索引移位、三个设置页面、最小窗口布局、实际打开并 Esc 关闭 ☰ 菜单，以及历史视图的全文搜索、Delete、
清空和无历史文件断言。5 个片段时弹窗为 920×452 物理像素、行高 68、Alpha=242，并断言 LB_GETTOPINDEX=0；
历史样本界面见 `docs/screenshots/clipboard-history.png`。

本轮自动化会话里 OpenClipboard、WinForms Clipboard 和系统 clip.exe 均持续返回“拒绝访问”(error 5)，所以历史两行内容使用
**仅 debug 且要求 VIBEKEY_DEBUG_INSTANCE 的样本消息**注入，release 不包含该入口。此次通过只证明历史视图和操作路径，
**不证明真实 WM_CLIPBOARDUPDATE 采集、Alt+V 真键盘触发或实际粘贴已经通过**；这些仍须按上方 P0 在可正常访问剪贴板的
交互桌面人工验收。调试样本不会写入发布构建，也不会在文档中被描述成真实复制测试。

同日新增加密设置隔离冒烟：在独立 APPDATA、同步网络功能未启用的条件下，验证两个加密密码依次保存、current/previous 轮换状态、
DPAPI blob 与 TOML 均不含 dummy 明文、清除后 sync-encryption.bin 删除；并人工查看默认/最小窗口截图。最小窗口曾裁掉冲突备份框，
已将紧凑布局上移并加入底部边界断言。Windows 单元测试另以 8 个线程共享真实 DpapiSecretStore，验证只有一次轮换成功、其余返回 RotationPending，
最终 current/previous 一致且可提交/清除；core 集成测试还验证解密坏 TOML 的秘密行不进入 sync-state.json。
该测试不替代真实 WebDAV 服务器与第二台机器的 P0 验收。

## P0 同步（WebDAV）

- [ ] 设置窗口填写 URL/用户名/密码，点“测试连接”成功。
- [ ] 保存后触发同步，远端出现 config.toml；本机 sync-state.json 生成。
- [ ] 第二台机器（不同 APPDATA 或虚拟机）配置同一 URL：首次同步拉取远端配置。
- [ ] 机器 A 改片段 → 同步 → 机器 B 同步：B 的配置更新，旧文件保留为 config.toml.bak。
- [ ] A、B 同时改不同片段后分别同步：后同步的一方本地优先，远端生成 config.toml.remote-backup-<时间戳>.toml，
      托盘提示冲突。
- [ ] 错误密码 / 断网：同步失败但程序不崩溃，日志与托盘提示合理，恢复网络后下次同步成功。
- [ ] 远端文件被删除：下次同步重新上传本地配置。
- [ ] 登录密码只存在于 DPAPI 加密的 secret.bin，配置加密密码只存在于 sync-encryption.bin；config.toml 不含任何明文密码，换机器需要重新输入。
- [ ] 勾选“加密远端配置正文”并输入独立密码后上传：远端主文件是 VIBEKEY 开头的二进制密文，搜索不到片段明文；本地 TOML 仍可编辑。
- [ ] 同一配置再次同步为 UpToDate 且无额外 PUT；新机器先勾选加密并输入同一密码后能拉取，拉取不会把 encrypt 改回 false。
- [ ] 旧明文远端启用加密后自动迁移；冲突时远端 `remote-backup` 也是密文，用相同密码可解密且内容确为旧远端。
- [ ] 错加密密码、修改任一密文字节、截断文件、把已加密远端替换为明文：均同步失败，本地配置不变，主远端不被强盖，不生成明文备份。
- [ ] 更换加密密码：旧密码可完成最后一次解密，新密文上传和状态保存后旧密码清理；第二次仅用新密码为 no-op。断网/保存状态失败时旧密码仍保留可重试。
- [ ] 本机已成功加密同步后，主动关闭且保留密码时可显式迁移回明文；无密码遇到加密远端必须失败。全新机器/原明文基线机器即使保存密码但漏勾加密，也必须拒绝而不能覆盖远端。
- [ ] 测试连接在加密远端上实际验证 current/previous；仅旧密码成功时提示可轮换。未建立本机加密基线时不得承诺可迁移为明文。
- [ ] 在 HTTP 联调环境确认正文虽已加密，但 Basic 登录凭据仍可能暴露；理解加密不替代 HTTPS、不隐藏元数据、不防服务器回滚旧密文。
- [ ] 自签名 HTTPS：留空 certificate_sha256 仍拒绝；填错误/非法指纹仍拒绝；填实际 DER SHA-256 后连接成功。设置页可保存该字段，最小窗口中指纹输入框不被底栏裁切。
- [ ] 指纹模式收到 HTTPS→HTTP 302 时必须失败且明文服务器无连接；未配置指纹的普通 HTTP 客户端仍可使用。

## P1 体验与兼容

- [ ] Alt 按住模式（设置里切换为“按住 Alt”）：快速 Alt+1 不触发；按住 Alt 超过 hold_ms 再按 1 触发。
- [ ] ignore_apps 中加入 notepad.exe：记事本中 Alt+1 不再触发（但列表热键仍可用？按设计只忽略片段/菜单触发）。
- [ ] 在管理员权限运行的记事本/任务管理器中按 Alt+1：不会注入，给出“权限更高”的提示。
- [ ] 目标程序自己使用 Alt+数字（例如某些 IDE、游戏）：用 hold 模式或 ignore_apps 规避；确认不会误吞其它按键。
- [ ] 输入法处于中文状态时 Alt+1：插入正常，输入法候选框不会卡住。
- [ ] 多显示器 / 125% 或 150% DPI：列表弹窗出现在光标附近且不超出屏幕，文字不模糊。
- [ ] 屏幕锁定/切换用户后：钩子与托盘仍工作。
- [ ] Explorer 重启（任务管理器结束 explorer.exe 再启动）：托盘图标自动恢复。
- [ ] 开机启动勾选后重启：自动运行且只有一个实例；取消勾选后重启不再自启。
- [ ] 退出时若有同步在跑：进程能正常结束（最多等几秒）。

## P0 Win7 专项

- [ ] Windows 7 SP1 x64 上运行 x64 版；32 位 Win7 SP1（或 WoW64 下运行 x86 版）均可启动。
- [ ] 未安装 UCRT / .NET 的干净 Win7 可运行（exe 只依赖系统 DLL）。

## 自动化冒烟的边界（2026-11-06 起）

- 钩子对 `LLKHF_INJECTED` 的按键一律忽略（见 `crates/vibekey-win/src/hook.rs` 的 `keyboard_proc`），
  所以 **SendInput/keybd_event 合成不出热键**；自动化只能覆盖托盘、右键菜单、设置窗口、单实例、退出这类
  不依赖按键的路径。热键相关条目必须用真键盘人工验证。
- 调试版可以打开测试口子：`set VIBEKEY_TEST_INJECTED=1` 后启动 `target\debug\vibekey.exe`，
  合成按键即可触发热键，配合 PowerShell 的 SendInput 脚本可自动回归 Alt+数字 / Alt+反引号。
  该分支包在 `#[cfg(debug_assertions)]` 里，release 构建（含 Win7 发布版）永远忽略注入输入。
- 需要与正在运行的正式版并行做 UI 测试时，调试版还可设置 `VIBEKEY_DEBUG_INSTANCE=UiSmoke`
  （仅字母/数字/连字符）使用独立单实例 mutex，并设 `APPDATA` 到临时目录隔离配置；release 忽略该变量。
- 往文本框里打字一律用 `KEYEVENTF_UNICODE`（VK_PACKET）注入：不经过输入法、不产生拼音候选，
  也不会和 `{clipboard}` 变量、剪贴板恢复互相干扰。
- 屏幕锁定时（LogonUI/LockApp 在跑、`GetForegroundWindow()` 返回 0）任何输入注入都不会到达窗口，
  自动化要先确认桌面未锁定。

## 本地 WebDAV 测试环境

快速起一个标准 WebDAV 服务器（任选其一）：

    # 方式 1: rclone（跨平台）
    rclone serve webdav --addr 127.0.0.1:8080 --user test --pass test /tmp/vibekey-dav

    # 方式 2: Python wsgidav
    pip install wsgidav cheroot
    wsgidav --host=127.0.0.1 --port=8080 --root=/tmp/vibekey-dav --auth=accept

然后设置：
    sync.url = "http://127.0.0.1:8080/config.toml"
    sync.username = "test"

注意：wsgidav 的 accept 模式不校验密码，仅用于功能验证。

## 已知限制（发布说明中必须保留）

- 无法向以管理员身份运行的程序注入文字（Windows UIPI 限制）。
- 全局 Alt+数字可能与个别程序快捷键冲突，使用 hold 模式或 ignore_apps。
- 剪贴板只保存/恢复纯文本；含文件/图片/富文本时程序改用逐字符输入，不覆盖剪贴板（长文本较慢）。
- 历史仅保存最近 50 条 Unicode 文本，退出清空；不保存图片、文件或富文本格式，不写磁盘、不同步。
- Win7 已于 2020 年停止官方支持，请仅在隔离/内网环境使用；网络同步建议仅使用 HTTPS + 应用密码。
